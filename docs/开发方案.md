# 个人版会议录音知识库 开发方案

日期：2026-08-21  
定位：单人、本机存储、可长期积累录音和转写的个人会议知识库；Windows 以可双击的 exe 为默认交付；项目源码以 Apache-2.0 开源发布于 GitHub，供他人自部署和二次开发。

本文是初期实施方案；`docs/会议智能完整版演进参考.md` 保留为后续多人版、企业版和合规增强的演进参考，不作为第一版实现范围。

## 0. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 项目许可 | Apache-2.0 | 含专利授权，利于二次开发 |
| 第一版推理位置 | **ASR 本机 FunASR Paraformer**；**LLM 远程 BYOK**；Embedding 默认不做 | 转写免费、音频不外发；只为报告/问答付 LLM。不把 PyTorch 打进 UI exe |
| 密钥归属 | 仅 LLM（及用户主动开的远程扩展）需要 Key | 项目不内置、不代理账单 |
| 默认 ASR | FunASR `paraformer-zh` + `fsmn-vad` + `ct-punc`，可选 `campplus` 说话人 | 中文会议；长音频必须 VAD 切段。权重 Apache-2.0，代码 MIT |
| 说话人 | 切片 0 验证 FunASR 是否**直接**输出 `SPEAKER_XX` 时间轴；若只给 embedding，则自动聚类为实验特性，默认 `SPEAKER_00` + 校对页人工拆分 | campplus 是说话人向量，不等于完整 diarization |
| 向量检索 | 第一版默认只用 jieba + FTS5；远程 Embedding 可选（额外云费） | 避免本机再叠 BGE；无向量时问答仍可用 |
| 行动项去重 | 仅同一会议的新旧报告版本 | 跨会同标题留给切片 3 合并 |
| 应用配置 | 程序目录 `app.json`（仓库根或 exe 旁） | `data_dir` 不能放在数据目录里自我引用 |
| 默认 zip | **不含** `portable.txt` | 默认即程序目录模式（`app.json`、`meeting-data`、`asr` 都在 exe 旁）；`portable.txt` 已废弃，出现也不改变路径，且禁止打进 zip |
| Windows 交付 | onedir exe + zip；pywebview 桌面窗口（WinForms + WebView2），缺 WebView2 回退系统浏览器 | 用户不必装 Python；不用 Electron / onefile |
| 监听端口 | 固定 `127.0.0.1:8787` | 用端口本身做单实例互斥；被其它程序占用则报错退出，不顺延 |
| 媒体鉴权 | `POST /api/session` 种 Cookie；`<audio src>` 可播 | 浏览器不能给 audio 加 Authorization。Cookie：`HttpOnly`、`SameSite=Strict`、`Path=/`；第一版 HTTP **不设 `Secure`、不设 `Domain`** |
| 问答传输 | `fetch` POST 读 `text/event-stream`（同源，默认带 Cookie） | `EventSource` 不能 POST，也不能带自定义头 |
| API 进程 | `--serve` 固定单进程 | 多 worker 会抢同一 SQLite |
| FFmpeg | 不嵌入；PATH 或 `ffmpeg\ffmpeg.exe` | 避免 GPL/LGPL 分发义务 |
| 本机 ASR 组件 | 第二包 `huiyiku-asr-windows-x64.zip`，内含 `huiyiku-asr.exe`；解压到程序目录 `asr\`（开发为仓库根 `asr\`） | UI 不含 Python/torch。唯一调用方式见 2.2：命令行出 JSON，不用 HTTP |
| 本机 LLM / BGE | 第一版不做 | 转写时内存已给 Paraformer，不叠本地大模型 |
| 产品标识 | 中文名「会议库」；仓库 / Python 包 `huiyiku`；exe `Huiyiku.exe` | 全项目同一套，禁止再混用 MeetingKB |
| 源码托管 | 个人账号下公开仓库 `huiyiku` | 不新建组织；只含本项目，不把其它工作目录一并推上去 |
| 二进制分发 | GitHub Release 附 Windows zip + SHA256 | 源码始终可克隆；exe 是附加资产，不是唯一获取方式 |
| 程序版本号 | 只写在 `pyproject.toml` 的 `[project].version` | runtime API 与 Git tag 都读这一处 |

## 1. 目标与非目标

### 1.0 原始需求追溯

| 原始需求 | 个人版处理 | 覆盖结论 |
|---|---|---|
| 会议录音后进入系统 | 导入本地音频/视频，不做自动入会 | 覆盖 |
| 识别声音并对参会人标记 | 校对页可新建、划段落、合并、映射到参会人。自动 `SPEAKER_XX` 仅当切片 0 证实 FunASR 管线直接输出标签；否则默认人工拆分 | MVP 覆盖“能标记”；自动区分说话人可能是实验特性 |
| 按时间和人物归纳统计 | 第一版做单场时间轴与人物统计；跨会议组/时间范围聚合统计放到切片 3 | 单场覆盖；跨会统计延后 |
| 问答查询会议内容 | FTS（默认）+ 可选远程向量 + 远程 LLM，回答带引用 | 覆盖；无 Embedding 仍可问 |
| 自动归纳重点并生成会议报告 | 远程 LLM 生成报告草稿，可人工修正后接受 | 覆盖 |
| 相关会议分组并总结项目进展 | 会议组、行动项追踪、项目进展摘要落库 | 本版覆盖持久化 |
| 个人初期使用 | Windows UI exe + 本机 FunASR 组件、localhost、SQLite、远程 LLM | 覆盖 |
| 优先可二次开发的开源协议项目 | 默认依赖树仅含宽松许可；不捆绑模型权重；远程服务条款由用户自行确认 | 覆盖代码侧；云服务不是开源许可问题 |

“识别声音”的边界必须明确：第一版用本机 FunASR 管线区分“不同声音”并输出时间分段，或由用户拆分；不做 voiceprint identification，即不自动判断“这是张三”。身份标记由用户在参会人名册中确认。

如果“识别声音”必须理解为自动识别具体身份，则放到后续增强（本机声纹样本），且须满足 7.4 的法律前提，不满足则不做。第一版仍不自动覆盖人工确认结果。

### 1.1 第一版目标

1. 导入本地音频或视频文件。
2. 生成带时间戳的转写；按人物统计单场发言时长、次数和占比。
3. 支持说话人重命名、合并、标记无效、手工新建并把段落划过去；允许一键接受自动标记。
4. 用远程 LLM 生成会议摘要、重点、决议、行动项、风险和未决问题；报告必须引用原文。
5. 对单场会议或多场会议问答，回答必须带原文引用。
6. 用“会议组”管理相关会议；基于已接受报告生成并保存项目进展摘要。
7. 维护每场会议的参会人名册；未发言参会人也能被记录。
8. 媒体、数据库、转写和报告默认保存在本机；备份 `app.json` 与数据目录即可迁移（ASR 组件需在新机器上重新安装）。
9. 转写默认本机 FunASR Paraformer；报告/问答用远程 LLM（BYOK）。Embedding 默认关闭。
10. Windows：UI 为可双击 exe（不含 PyTorch）；ASR 为单独安装的本机组件。开发者可用源码 venv。

### 1.2 第一版不做

以下能力全部延后，不进入个人版 MVP：

1. 多用户、登录、RBAC、SSO、组织架构。
2. 项目成员、审批流、法律保留、审计假名、保留策略引擎。
3. 会议机器人自动入会、日历联动、实时转写。
4. 移动端、多租户、把知识库做到云端协作。
5. MinIO/S3、Redis、Kubernetes、OpenSearch。
6. 复杂行动项审批、多人负责人和行动项合并 UI（合并放到切片 3）。
7. 自动声纹身份识别。法律前提见 7.4（PIPL 第 28–29 条 / GDPR 第 9 条）；不满足则不做。
8. **本机 LLM、本机 Embedding（BGE）、Ollama**。本机 ASR（FunASR Paraformer）在第一版默认启用，但是 **独立组件**，不打进 UI exe。
9. 跨会议组/时间范围的人物趋势统计页（切片 3）。
10. 商业分发（打包售卖或闭源集成）；当前只做 GitHub 开源分享。GitHub Release 提供免费 Windows exe **不等于**商业分发，见 1.4。
11. ~~Electron / WebView2 壳~~（**已提前实施**：pywebview + WebView2 桌面窗口，见 1.3）、系统托盘常驻、自动更新、macOS `.app` / Linux 包。托盘与自动更新仍在切片 3。

### 1.3 使用方式

第一版对终端用户是 **Windows 桌面程序**，对开发者仍是本机 Web 应用：

1. Windows：解压 zip 后双击 `Huiyiku.exe`。引导进程拉起 API 与 Worker，然后打开 **pywebview 桌面窗口**（标题「会议库」，WinForms 窗口内嵌 WebView2 渲染同一 Web 界面；启动时按主屏分辨率钳制窗口尺寸）。机器缺少 WebView2 或 .NET 时自动回退：系统浏览器打开 `http://127.0.0.1:8787` + 最小 tkinter 状态窗口。窗口关闭即停 API/Worker 并做 WAL checkpoint；Worker 崩溃由看门狗线程自动重启一次。
2. 后端默认只监听 `127.0.0.1`。
3. 终端用户 **不必安装系统 Python / Node / CUDA**。界面用 UI zip；转写再解压 ASR zip 到 `asr_home`（内含 `huiyiku-asr.exe` 与 torch，约数 GB）。开发者 Web venv 不含 torch，ASR 用 extra `[asr]` 跑同一 CLI。
4. 媒体、数据库、转写、报告和导出保存在数据目录（见 2.4）。ASR 组件与权重在程序目录 `asr\`（开发为仓库根 `asr\`），**不进 Git、不打进 UI zip**。
5. **转写不依赖外网。** 无 LLM Key 时仍可导入、转写、校对、统计、导出。报告、问答、组摘要需要远程 LLM 和网络。
6. FFmpeg 与 FunASR 均须可用：FFmpeg 走 PATH 或 `ffmpeg\ffmpeg.exe`；FunASR 走 ASR 组件检测。缺任一则向导说明如何安装，不静默失败。不建议没有 16GB 内存时边开大量浏览器边转写一小时会。

不直接暴露到公网。内部小范围使用不要求访问令牌：`access_token` 为空时接口全放行。若仍配置了令牌，浏览器先 `POST /api/session` 换 Cookie（`HttpOnly`、`SameSite=Strict`，不设 `Secure`）；API 也可接受 `Authorization: Bearer`。`<audio>` 与导出链接走 Cookie，不把令牌写进 URL。

内网共享由设置页开关控制（`settings.json` 的 `share_lan`，默认关）。进程固定监听 `0.0.0.0:8787`，这样开关可以立刻生效、不必重启桌面窗口。关闭时中间件拒绝非本机请求。旧的 `app.json` `host=0.0.0.0` 且还没有该字段时，启动一次即写成开启。HTTPS 延后。仍然不做多人权限体系。

内网共享（可选、文档化）：开关打开后，可信内网的几人可用浏览器直接访问同一库，不必先设令牌。明文 HTTP、无按人审计、转写全员排队、宿主机在线才可用——完整边界见 README「内网共享」与 SECURITY.md。

单实例：本应用独占 `127.0.0.1:8787`。已在运行时，再次双击打开桌面窗口（或缺 WebView2 时回退系统浏览器），不启动第二套 API/Worker。8787 已被其它程序占用则状态窗口报错并退出，不改绑其它端口。

### 1.4 开源发布策略

本项目以**独立公开 GitHub 仓库**发布，供他人克隆、自部署和二次开发。不要把本方案所在的其它工作目录推上网。

| 层级 | 场景 | 合规义务 |
|---|---|---|
| 自用 | 本人本机运行 | 无分发行为，不触发开源义务；远程 API 受该服务条款约束 |
| 开源分享（本项目默认） | 公开仓库 + GitHub Release（UI zip 与 ASR zip 分开） | 见 2.11；UI zip **不捆绑** FunASR/PyTorch/FFmpeg/Key |
| 商业分发 | 打包售卖或闭源集成 | 触发 2.7 完整门禁，当前不做 |

关键边界：公开源码不等于分发模型权重，也不等于提供云推理。Release 里的 zip 是把本项目与宽松依赖冻成可执行文件，仍属开源分享，zip 内必须有 `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`。

项目许可 **Apache-2.0**。入站贡献默认同样按 Apache-2.0（README / CONTRIBUTING 写明）。仓库根目录必须有 `LICENSE` 与 `NOTICE`。

## 2. 简化架构

### 2.1 组件

```text
Huiyiku.exe（引导进程：单实例、pywebview 桌面窗口、看门狗）
  |-- FastAPI API + 内置静态前端     （--serve，无 PyTorch）
  |-- Worker                         （--worker，无 PyTorch）
        |-- FFmpeg CLI
        |-- 本机 ASR 组件（独立进程/venv：FunASR Paraformer + VAD + 标点 + 可选 CAM++）
        |-- 远程 LLM（BYOK，仅报告/问答/摘要）
  |
SQLite + Local File Storage
  |
pywebview 桌面窗口（WebView2 渲染）→  http://127.0.0.1:8787
  └─ 缺 WebView2/.NET 时：系统浏览器 + tkinter 状态窗（回退路径）
```

API / Worker **不 import torch、不 import funasr**。转写时 Worker **只**启动 `asr_home\huiyiku-asr.exe`（开发态为 `.venv-asr` 或 `python -m huiyiku_asr`，同一套 CLI），从 stdout 读 JSON 分段。不用本地 HTTP。ASR 崩溃不影响界面进程。

Worker 分两条执行道：媒体（`preprocess` / `transcribe`）串行 1 槽；推理（`stats` / `embed` / `report` / `digest`）默认 1 槽，可用环境变量 `HUIYIKU_INFERENCE_SLOTS` 提到最多 2。媒体转写时推理仍可跑。

两者只通过 SQLite `jobs` 表通信。冻成 exe 后，`--serve` / `--worker` 仍用 `sys.executable`。`--serve` 只起 1 个 Uvicorn 进程。WAL + `busy_timeout=30000`。问答用异步 httpx 调远程 LLM。引导进程通过 `HUIYIKU_PARENT_PID` 让子进程守望父进程，避免孤儿占 8787。

### 2.2 技术选型

| 层级 | 第一版默认 | 原因与扩展边界 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI | 文件上传、任务查询、调用远程 HTTP |
| 前端 | React + Vite | 转写校对、播放、问答和统计 |
| 数据库 | SQLite + WAL | 个人数据量足够，运维成本最低 |
| 中文检索 | jieba 分词 + SQLite FTS5 | 不引入 PostgreSQL；FTS 使用预分词文本，不写 jieba C tokenizer |
| 向量检索 | 默认关闭；可选远程 embeddings 写入 BLOB | 第一版问答靠 FTS；sqlite-vec 切片 3 |
| 任务队列 | SQLite `jobs` + 独立 Worker | 媒体型串行（含本机 ASR，避免两场同时占满内存） |
| 文件存储 | 本地数据目录 | 备份和迁移简单 |
| 音频处理 | 用户自备 FFmpeg CLI | 抽音轨、16kHz 单声道 WAV；**不必再压 mp3 外发** |
| ASR | 本机 FunASR Paraformer + fsmn-vad + ct-punc | 精确模型 ID 见切片 0 登记；长音频必须 VAD |
| 说话人分离 | FunASR `spk_model=campplus`（说话人向量） | 切片 0 验证是否开箱即出带标签时间轴；否则不自研聚类，默认人工拆分 |
| Embedding | 默认无 | 用户可选手动开远程 embeddings（额外云费） |
| LLM | 远程 OpenAI-compatible Chat Completions | 不在本机跑 Ollama |
| HTTP 客户端 | httpx | 仅 LLM（及可选远程扩展） |
| 打包（Windows） | UI：`huiyiku-windows-x64.zip`（无 torch）。ASR：`huiyiku-asr-windows-x64.zip`（含 torch CPU + FunASR + `huiyiku-asr.exe`） | 两包分开发；禁止把 PyTorch 冻进 `Huiyiku.exe` |
| 状态窗口 | Python 标准库 tkinter | 冻进 UI exe |

默认可跑通组合：

| 任务 | 默认 | 最低能力 |
|---|---|---|
| ASR | Hugging Face / ModelScope 的 Paraformer 中文权重 + fsmn-vad + ct-punc | 分段文本 + 起止 ms；切片 0 记下精确 model ID、revision、checksum、许可 |
| 说话人 | campplus / CAM++（FunASR `spk_model`） | 可选；装不上则人工拆分 |
| LLM | DeepSeek / 通义 compatible / 硅基流动 / OpenAI 等 | JSON 输出；登记 `context_length` |
| Embedding | 关闭 | 开了才做向量检索 |

切片 0 必须在目标 Windows 上实测并记录：FunASR 安装体积、转写峰值内存、1 小时会耗时、是否出说话人；再用同一转写走远程 LLM 摘要，记录 token 与费用。CI **不**安装 torch、不跑本机 ASR。

ASR **唯一**对外合同（本机，不上传音频）：

```text
huiyiku-asr.exe transcribe --wav <16kHz_mono.wav>
```

可选 `--model-dir`；省略时用环境变量 `HUIYIKU_ASR_MODEL_DIR`，再省略则用 `asr_home`（默认程序目录 `asr`，开发为仓库根 `asr`）。**开发态与 exe 态同一目录**：权重只落在 `asr_home`（建议子目录 `models/`），FunASR 禁止用包内或 `_internal` 相对路径加载，否则两种形态会各下一份模型。

- 标准输出（完成后一次）：JSON 数组 `[{ "start_ms", "end_ms", "text", "speaker_label": null|string }]`
- 标准错误：进度行，每行一个 JSON，至少 `{"event":"heartbeat"}`；建议 `{"event":"segment","i":n,"n":m}`
- 退出码 0 成功，非 0 失败（stderr 可含 `{"event":"error","message":"..."}`）
- 取消：Worker 结束该进程；ASR 在 VAD 段间隙检查，尽快退出
- 开发态等价：`python -m huiyiku_asr transcribe --wav ...`（同一 `--model-dir` / `asr_home`）

实现必须：VAD 切段后再送 Paraformer；不把整小时 WAV 一次载入模型。Worker 轮询 stderr 心跳，不解析 FunASR 内部 API。

**说话人（切片 0 第一天验证）：** `campplus` 是说话人 **embedding**，不是完整 diarization。必须实测 `paraformer + fsmn-vad + ct-punc + campplus` 是否**直接**给出带 `SPEAKER_XX` 的分段时间轴。

- 若直接输出标签：第一版默认启用，DER 按 8.4。
- 若只输出逐段向量、聚类要自写：第一版 **不实现**谱聚类/调参。`speaker_label` 恒为 null，整场落成 `SPEAKER_00`，校对页人工拆分（路径已有）。自动区分说话人标为实验特性，README 写明。不得在切片 1 才发现缺聚类管线。

### 2.3 模型可选与切换规则

四类能力仍走统一 Provider 接口。第一版默认：ASR / 说话人 `execution=local`，LLM `execution=remote`，Embedding 不设默认。

| 任务 | 第一版 | 后续增强 |
|---|---|---|
| ASR | 本机 FunASR Paraformer + VAD + 标点 | 远程 ASR 仅作可选扩展（额外云费，默认关） |
| 说话人分离 | 本机 CAM++（FunASR spk） | pyannote 仍仅手动、gated |
| Embedding | 关闭；可选远程 | 本机轻量中文向量 |
| LLM | 远程 chat completions | 本机 Ollama |

选择规则：

1. 四类任务的全局默认模型唯一保存在 `model_registry.is_default`，只通过 `PATCH /api/models/{id}` 设默认。`settings.json` 只保存报告、问答、项目摘要三个角色级 LLM 覆盖，未设置时回退到注册表 LLM 默认。`PATCH /api/settings` 不得改 Embedding/ASR 默认。密钥不进注册表，见 7.1。
2. 切片 1 和 2 中，创建转写、生成报告、生成摘要和发起问答一律使用默认模型（注册表默认加角色级覆盖）。请求级显式传 `model_id` 属切片 3。变更只影响之后的新任务；进行中的任务和已完成产物不变。产物始终记录实际 `provider + model + version`。
3. 已完成结果不因默认配置变化而自动重跑；只有用户主动重跑才生成新结果。
4. **第一版禁止在已有激活向量时更换 Embedding 默认模型。** 接口返回明确错误，提示切片 3 的重建命令。检索只使用 `embedding_model` 与当前默认一致且维度相同的 Chunk；无向量时退回 FTS，不得对混维做余弦。全量重建仍属切片 3。
5. 本机 ASR 不要求 `allow_cloud`。远程 LLM / 远程 Embedding / 远程 ASR（若用户手动开）必须 `allow_cloud=true` 且条款已确认。仅在会把内容送出本机的入口显示外发提示（报告、问答、摘要、以及用户打开的远程 ASR），**不要**在本机转写按钮上写“音频将发到云端”。
6. `allow_cloud=false` 时禁止 **远程** embed / report / digest / qa / 远程 ASR；**本机 transcribe 仍可运行**。
7. 未通过连通性测试的远程 LLM 不能设为默认。本机 ASR 设为默认前必须：权重 checksum 匹配、VAD 试跑一小段合成音频成功。
8. LLM 可以不配置：转写、校对、统计仍可用；报告、问答、项目摘要入口禁用并说明原因。
9. 本机 ASR 组件未就绪时不能创建转写任务，向导给出安装步骤。Embedding 未配置时 indexing 只做 FTS 和统计。
10. 第一版默认禁止把远程 ASR 设为默认（避免用户在不知情下付转写费、外发音频）。

### 2.4 应用配置与数据目录

**应用配置**与**数据目录**必须分开。`data_dir` 不得只写在数据目录内的 `settings.json` 里，否则启动时无法定位自己。

应用配置文件 `app.json`（不含密钥）：

录音、库文件和 ASR 组件默认都跟着程序目录走，解压后请放到固定位置，不要留在「下载」。**默认 Release zip 不得包含 `portable.txt`。**

数据目录：

```text

  media/original/
  media/wav/
  media/waveform/

  reports/
  exports/
```

禁止把库写进 `_internal` 或 `Program Files`。`backups/` 放在数据根的上一级。ASR 权重与 torch 环境在 `asr_home`，**不进 meeting-data 备份也可以**（可再下载）；备份说明里写清这一点。

检测到数据目录位于 OneDrive / 网络盘时启动警告，向导建议改到本地磁盘（写 `app.json` 的 `data_dir`）。

### 2.6 自由使用优先策略

第一版“自由使用优先”作用于**代码默认依赖**，不作用于远程推理：

### 2.8 运行环境要求

1. 目标平台：Windows、macOS、Linux。**终端用户验收以 Windows exe 为准**；macOS / Linux 第一版只保证源码 + 启动脚本。
2. 终端用户跑界面：64 位 Windows 10+、WebView2 运行时（Win10/11 一般自带；缺失自动回退系统浏览器）、FFmpeg。跑本机转写：再加 ASR 组件；**推荐 16GB 内存 + SSD**；8GB 能试但转写时请少开浏览器。GPU 非必须（CPU 约 15× 实时）。LLM 需要网络。
3. 开发者：Python 3.12、Node、FFmpeg；Web venv 无 torch；另建 `asr` venv 或 extra `[asr]` 装 FunASR。
4. Windows 专项：FFmpeg 按 2.10 的查找顺序检测并记录版本输出；数据目录和媒体路径必须兼容中文与空格；SQLite 不得放在网络盘或同步盘（如 OneDrive），WAL 在这些场景不可靠。
5. **仅界面：8GB 可浏览。本机转写：推荐 16GB。** 切片 0 硬门槛：16GB 机器转写 1 小时会，峰值内存须 ≤ 8GB。超标时按 **2.8.7 阶梯降级**（CAM++ 不是内存大头，只关它可能不够）。不需要 GPU。
6. 磁盘：每小时 WAV 约 115MB；ASR 组件另约 4–8GB。UI zip **< 120MB**，不得打进 torch / FunASR 权重。
7. 切片 0 必须实测：FunASR 峰值内存、1 小时会耗时、说话人管线是否直接出标签、LLM 摘要 token 与截断。内存超 8GB 时按下列顺序降级并写入 README：① 关闭 CAM++；② 仍超则改用更小 Paraformer 或缩短 VAD 切段；③ 记录实测硬件表。切片 2：无系统 Python 时 UI exe 能开向导（转写仍要已装 ASR 组件）。

### 2.10 Windows 打包与进程模型

打包器：PyInstaller onedir。理由：jieba / SQLAlchemy / FastAPI 钩子成熟；目录包启动快于 onefile，Worker 可复用同一 `_internal`。PyInstaller 只出现在 `requirements-build.txt`。若构建工具必须完全落在 2.7 白名单内，改为 cx_Freeze。

引导进程职责：

1. 绑定 `127.0.0.1:8787` 作为单实例互斥。绑定失败且端口已被本应用占用：直接开桌面窗口（或回退浏览器）后引导进程退出。绑定失败且占用者不是本应用：报错退出。
2. 读取 `app.json`（2.4），解析数据目录，拒绝写到 `_internal`。
3. 查找 FFmpeg：`ffmpeg_path` → exe 同级 `ffmpeg\ffmpeg.exe` → `PATH`。查找 ASR：`asr_home\huiyiku-asr.exe`（开发态则 `python -m huiyiku_asr`）。找不到则允许启动 UI，转写任务失败并指向「请安装 ASR 组件 zip」。
4. 启动 `Huiyiku.exe --serve`（单进程）与 `Huiyiku.exe --worker`，传入 `HUIYIKU_PARENT_PID` 供子进程守望（父进程消亡即自退）。Worker 退出码非 0 时自动重启一次，仍失败则状态窗口报错，不无限拉起。
5. 打开 pywebview 桌面窗口（`webview.platforms.winforms.renderer == 'edgechromium'` 可用时）；否则回退系统浏览器 `http://127.0.0.1:8787` + tkinter 状态窗口（地址、打开浏览器、退出、“添加本地文件”）。添加本地文件 = **新建一场会议**，`shutil.copy` 进 `media/original` 后入队 preprocess，不挂到当前正在看的会议。
6. 退出时先停 Worker、再停 API，并 checkpoint。
7. 捕获未处理异常到数据目录 `logs/`，不要只闪退。

冻结清单必须显式收集：jieba 词典、**tcl/tk**、前端 `dist/`、迁移文件、`LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`。禁止打进 numpy、`.env`、`secrets.json`、真实录音、`portable.txt`。

不做：管理员安装到 `Program Files`、开机自启、自动更新、代码签名（切片 3）。zip 解压即用；推荐解压到 `%LOCALAPPDATA%\Programs\Huiyiku`。

GitHub 上的 Windows zip **未签名**。Release 说明必须写：SmartScreen / 杀毒可能误报；以本仓库 Actions 构建的 zip 与 `SHA256SUMS` 为准；不要从第三方网盘下载。第一版不上传到微软公证，也不保证过 Defender 云查。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | Chunk ID |
| `meeting_id` | INTEGER FK | 会议 ID |
| `group_id` | INTEGER FK | 冗余，随会议移动同步 |
| `speaker_id` | INTEGER FK | 主要说话人，可空 |
| `start_ms` | INTEGER | 开始 |
| `end_ms` | INTEGER | 结束 |
| `chunk_type` | TEXT | transcript / summary / decision / action / risk / question |
| `content` | TEXT | 原文 |
| `tokenized_content` | TEXT | jieba 空格分词，供 FTS5 |
| `embedding` | BLOB | 向量；无 Embedding 模型时为空 |

切分规则：

1. 以确认后的说话人轮次为边界聚合，目标每 Chunk 30 到 120 秒且不超过 300 字，超出时在句边界切分。

3. 摘要、决议、行动项、风险、未决问题按条目单独成块，并记录来源报告版本。
4. 说话人未确认或标记无效的转写按时间窗口切分，不记 `speaker_id`。

### 3.11 `action_items` 与 `action_item_events`

| 表 | 关键字段 |
|---|---|
| `action_items` | `group_id`, `source_meeting_id`, `source_report_version_id`, `title`, `owner_person_id`, `status`, `priority`, `due_at`, `evidence_json`, `merged_into_id`, `origin`, `updated_at` |
| `action_item_events` | `action_item_id`, `from_status`, `to_status`, `reason`, `meeting_id`, `created_at` |

状态：`open / doing / blocked / done / cancelled`。`origin`：`report_extract` / `manual`。

写入规则（第一版，不做跨会合并 UI）：

1. 只有 **当前 accepted** 报告版本会抽取行动项。
2. 接受同一会议的新版本时：按该会议内 `title + owner_person_id` 去重；本场已有且未 `cancelled` 的不插入，只记事件“新版本再次提到”。**不与其它会议的同标题去重**（跨会合并属切片 3）。
3. 用户手工改过的字段（负责人、状态、截止日期）不被报告覆盖。
4. `manual` 条目不因报告重跑而删除。
5. `origin=report_extract` 且来自已被取代的旧 accepted 版本、用户从未改过状态的条目：随新版本接受保持原状，不自动取消。

### 3.13 `jobs`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 任务 ID |
| `meeting_id` | INTEGER FK | 会议任务必填，其它可空 |
| `type` | TEXT | preprocess / transcribe / stats / embed / report / digest |
| `status` | TEXT | queued / running / success / failed / cancelled |
| `payload_json` | TEXT | 输入参数 |
| `progress_json` | TEXT | 阶段与百分比 |
| `error_json` | TEXT | 错误；含 HTTP 状态、可重试标记，不含 Key |
| `usage_json` | TEXT | 音频秒数、token、调用次数 |
| `idempotency_key` | TEXT UNIQUE | `meeting_id + type + 输入哈希 + 模型版本` |
| `attempt_count` | INTEGER | 重试次数 |
| `timeout_seconds` | INTEGER | 按类型默认值 |
| `heartbeat_at` | TEXT | Worker 心跳 |
| `cancel_requested` | INTEGER | 协作式取消 |
| `created_at` | TEXT | 创建 |
| `started_at` | TEXT | 开始 |
| `finished_at` | TEXT | 结束 |

独立 Worker 进程。源码态用 `python -m huiyiku worker`；exe 态必须 `sys.executable --worker`。两条执行道：

- **媒体型（串行）：** preprocess、transcribe。同一时间只跑一个，避免两场 FunASR 同时占满内存。
- **推理型：** stats（本地快）、embed、report、digest。默认并发 1，可配置到 2。避免一场长转写阻塞另一场的报告。

默认超时：preprocess 30 分钟；transcribe 2 小时（本机 CPU 一小时会通常数分钟，宽限用于低配）；embed 1 小时；report 45 分钟；digest 30 分钟。ASR 切段与每段推理期间必须每 15–30 秒写 `heartbeat_at`。心跳超过 `timeout_seconds` 的 `running` 任务，Worker 启动时重置为 `queued`（`attempt_count+1`，超过 3 次变 `failed`）。

`POST /api/jobs/{id}/cancel` 置 `cancel_requested=1`；轮询间隙检查；不能保证立即取消云端任务。

问答**不进 jobs**，在 API 进程用异步 httpx 流式转发；禁止同步阻塞整个事件循环。

任务类型与会议状态：

| job type | 会议状态 |
|---|---|
| preprocess | preprocessing |
| transcribe | transcribing |
| stats / embed | indexing |
| report | report_draft（仅当 LLM 已配置且用户请求生成） |

digest 不改变会议状态。问答不进 jobs，由 API 异步流式转发。stats 在无 Embedding 时单独完成即可进入 `indexed`。

### 3.17 会议编辑、删除与失效重算

1. `PATCH /api/meetings/{id}` 可改标题、会议时间、会议组；改组时同一事务更新 `meetings.group_id` 和全部 `meeting_chunks.group_id`。
2. `DELETE /api/meetings/{id}` 删除会议及派生数据：`media/` 下文件、`speaker_turns`、`meeting_speakers`、`transcript_segments`、`speaker_stats`、`meeting_chunks`（含 FTS）、`reports` / `report_versions`、`meeting_participants`、关联 `jobs`。若该会仍有 `queued`/`running` 任务，必须先协作式取消并等到 Worker 放下文件句柄，再删文件；超时则返回 409，提示稍后重试。
3. 行动项：`origin=report_extract` 且 `source_meeting_id` 为该会议、未被其它会议事件引用、`merged_into_id` 为空 → 物理删除。其余保留，`source_meeting_id` 置空，前端显示“原会议已删除”。
4. 删除前接口先返回影响清单；确认后执行。个人版无回收站。
5. `qa_messages` 和 `group_digests` 保留；引用失效时显示“原会议已删除”。

失效重算：

| 操作 | speaker_stats | transcript chunks / FTS / 向量 | 报告 |
|---|---|---|---|
| 确认说话人（进入 indexing） | 重算 | 重建 transcript chunks；有 Embedding 则请求向量 | 不自动生成；用户点生成 |
| 合并 / 标记 invalid / 改 person | 重算 | 更新 speaker_id，必要时重建 | 置 `stale_reason` |
| PATCH 转写文本 | 次数可变则重算 | 旧 chunk 失效，写新 chunk，按需重 embed | 置 `stale_reason` |
| 接受报告 | 不变 | 写入 summary/decision/action/risk/question chunks | 该版本 `accepted` |
| 移动会议组 | 不变 | 只改 `group_id` | 不变 |

### 3.18 索引、外键与迁移

切片 1 一次建齐全部表。使用 Alembic 或等价迁移脚本，禁止手改生产库。

最低索引：

- `meetings(group_id, occurred_at)`、`meetings(status)`
- `transcript_segments(meeting_id, start_ms)`
- `meeting_chunks(meeting_id, is_active)`、`meeting_chunks(group_id, is_active)`
- `jobs(status, type)`、`jobs(meeting_id)`
- `action_items(group_id, status)`
- `qa_messages(session_id)`

外键默认 `ON DELETE` 由 3.17 应用层事务处理，不依赖 SQLite 级联以免漏 FTS 与文件。

## 4. 处理流水线

### 4.1 状态机

| 状态 | 说明 | 用户能做什么 |
|---|---|---|
| `created` | 已创建，等待媒体 | 上传 |
| `preprocessing` | FFmpeg 抽音轨、转 WAV、可选压缩、峰值 | 等待 |
| `transcribing` | 本机 FunASR 转写中 | 等待；可取消 |
| `speaker_review` | 转写已落库，等待确认说话人 | 校对、一键接受自动标记 |
| `indexing` | 统计、分词、远程向量 | 等待 |
| `indexed` | 知识库可用 | 单场统计、问答（有 LLM 时）、导出；可再生成报告 |
| `report_draft` | 有草稿 | 编辑、接受 |
| `ready` | 至少一份报告已接受 | 问答、组摘要可引用该会高置信结论 |
| `failed` | 失败 | 从指定阶段重试 |

LLM 未配置时，会议在 `indexed` 即达到第一版“能用”状态，不得卡死等待报告。问答在 `indexed` 及之后开放（基于转写 Chunk）；组摘要只使用已接受报告。

### 4.2 处理步骤

1. 导入：校验格式、大小（流式计数，达 `max_upload_gb` 即中断）、时长。支持 WAV、MP3、M4A、MP4。浏览器拖拽走 `POST .../media`。大文件可用状态窗口“添加本地文件”（新建会议，本机拷贝）。
2. FFmpeg：16kHz、单声道、16bit WAV，写 `duration_ms`。本机 ASR 只吃这份 WAV，不再为外发另压 mp3。波形峰值生成（展示属切片 3）。
3. `transcribe`：Worker 调用 `huiyiku-asr.exe transcribe --wav <wav>`（合同见 2.2）。stderr 心跳，stdout 一次 JSON。落库后才改状态。
4. 说话人：仅当切片 0 证实管线直接输出标签时写入 `SPEAKER_XX`；否则整场 `SPEAKER_00`，校对页人工拆分。
5. 停在 `speaker_review`。允许“接受自动标记”。校对页可 **新建说话人**、多选段落改归属（拆分）、合并、绑定人员。
6. 确认时优先从本场名册、别名、同组历史映射给候选；写入 `person_id` 并入册。
7. `POST .../speakers/approve` 返回 `job_id`，入队 stats，若已配 Embedding 再入队 embed，完成后进入 `indexed`。
8. 术语表属切片 3，此前 normalized 直通。
9. 用户请求生成报告时入队 `report`（须有 LLM）。map-reduce 见 5.5。
10. 用户编辑并接受报告；抽取行动项按 3.11。

异步约定：上传完成后的预处理、重试、确认说话人、生成报告、生成摘要均返回 `202` + `job_id`。流式上传本身是长 HTTP，服务端关闭该请求的空闲超时。

### 4.3 失败恢复

1. 每个阶段输出落库或落文件后才更新会议状态。
2. 重试从指定阶段开始；`transcribe` 成功后不得无故重跑本机 ASR，除非用户明确“重新转写”。
3. Worker 崩溃后重启，按心跳回收超时 `running` 任务。
4. 报告重试创建新草稿，不覆盖已有版本。
5. 远程 401/403：任务失败，提示检查 Key，不盲目重试。
6. 取消后会议回到上一稳定态（有转写则 `speaker_review` 或 `indexed`，否则 `created`）。

## 5. 会议报告、问答与项目汇总

### 5.1 报告结构

```json
{
  "summary": "会议摘要",
  "key_points": [
    { "content": "重点", "speaker_id": 3, "person_id": 1, "time_ms": 120000, "segment_ids": [1] }
  ],
  "decisions": [
    { "content": "", "speaker_id": null, "person_id": null, "time_ms": 0, "segment_ids": [] }
  ],
  "action_items": [
    { "title": "", "owner_person_id": null, "due_at": null, "priority": "normal", "segment_ids": [] }
  ],
  "risks": [],
  "open_questions": [],
  "participants": [
    { "person_id": 1, "name": "张三", "spoke": true }
  ]
}
```

生成规则：

1. 每条关键结论必须引用转写片段 ID 和时间。
2. 引用文本必须能在转写中找到；匹配前去掉空白并将中英文标点规范到同一形式。
3. LLM 输出必须通过 JSON Schema 校验。
4. 无法确定负责人时写 `null`，不猜测。
5. 先 draft，用户可编辑，接受后进入高置信检索。
6. 说话人用 `speaker_id` / `person_id`；展示名由名册渲染。
7. “接受自动标记”时报告头部必须标注“说话人未人工校对”。

### 5.2 问答

检索范围：单场、一个会议组、多个会议组、时间范围、指定人物、指定类型（转写 / 决议 / 行动项 / 风险 / 摘要）。

流程：

1. 解析问题与过滤条件。
2. FTS5 关键词检索。
3. 若有激活向量：应用层余弦 Top N。
4. RRF 融合，`k=60`。
5. 取 Top 20，按 LLM `context_length` 压缩：系统提示 + 引用 + 问题合计不超过预算 80%。
6. 调用远程 LLM，SSE 把 token 转给浏览器，完成后落库。
7. 引用校验。失败时答案仍返回，但每条引用带 `verified: false`，界面标明“引用未通过原文校验”，不撤回整段已流式内容。

资料不足时回答“没有找到”，不得编造。`POST /api/qa` 返回 `text/event-stream`。前端必须用 **`fetch` POST 读取流**，禁止 `EventSource`（不能 POST，也不能带 Authorization）。问答在 `indexed` 后即可对转写进行。API 进程内使用异步 httpx，不得阻塞其它请求。

### 5.3 会议组汇总

数据来源：已接受报告、行动项状态和事件、时间范围内的风险和决议。可选包含未接受草稿，必须标记“待确认”。

```json
{
  "period": "2026-08-01 到 2026-08-21",
  "progress": [],
  "decisions": [],
  "risks": [],
  "action_items": [],
  "next_steps": [],
  "source_meetings": []
}
```

每条进展必须能跳回会议报告或转写原文。`POST` 返回 `job_id`。该组在时间范围内 **没有已接受报告** 时不创建任务，返回 400，提示先接受至少一份会议报告。

### 5.4 单场人物与时间统计

第一版页面只做**单场** `GET /api/meetings/{id}/stats`。跨会聚合接口可先在后端留路由，页面放到切片 3。

规则：

1. `merged` 和 `invalid` 不参与统计。
2. 重叠语音按当前确认归属，不在多人之间重复累计。
3. `speech_ratio` 分母见 3.8。
4. 页面展示 `metric_version`。

### 5.5 LLM 上下文与长会议策略

一小时中文转写约 2 到 4 万 token。远程模型常见 32k–128k，仍可能不够或被静默截断。

1. 登记每个 LLM 的 `context_length`（输入窗口）。`max_tokens` 只表示输出上限，不能用来“撑开”窗口。多数 OpenAI-compatible 服务的窗口是模型固有的，长会议仍靠 map-reduce。
2. 若整场转写 token < `context_length` 的 60%，报告可以一次生成；否则 map-reduce：按 Chunk 分组（每组约窗口 60%）抽取，再汇总。两级 Prompt 版本分别记录。
3. 问答超预算时优先保留关键词命中，并写明“已省略部分材料”。
4. 项目摘要对多场已接受报告两级汇总。
5. 切片 0 必须用不少于 1 小时录音验证：日志记录每次调用的输入 token 与截断计数（若 API 返回），证明策略覆盖全部转写。

### 6.3 界面设计原则与关键交互

不引入大型 UI 组件库；允许极小的无样式工具（虚拟滚动可用 MIT 的 TanStack Virtual）。用 CSS 变量管理令牌。

设计基调：专业桌面工具，信息密度优先；支持跟随系统的暗色模式。切片 1 建立最小令牌：主色、成功、警告、错误各 1，文字 3 级，间距 4 档，字号 4 档，圆角 2 档。

全局交互：

1. 异步操作必须有进行中状态；超过 3 秒显示步骤或进度。
2. 删除会议等破坏性操作二次确认，并列出影响。
3. 每页有空状态和引导。
4. 步骤条：预处理 → 转写 → 校对 → 索引 →（可选）报告。失败步骤可点重试。外发步骤显示云端提示。

会议详情：

```text
┌─────────────────────────────────────────────────────────┐
│ 会议标题  时间  组  [编辑] [删除]          [步骤条: 校对中] │
├──────────────────────────────┬──────────────────────────┤
│ 转写列表（虚拟滚动）          │ 播放器                    │
│ ▶ 00:12:34  张三(已确认)      │ ▶ 播放  1x                │
│   这个季度的目标……            │ 说话人统计               │
│ [校对进度: 12/47 段]          │ [报告] [问答] [参会人]    │
└──────────────────────────────┴──────────────────────────┘
```

1. 点击转写段落跳转播放；播放中列表跟随高亮（可关）。`<audio src>` 指向 `GET .../audio`（支持 Range），依赖会话 Cookie，不要用 fetch 把整段 WAV 读进内存。
2. 按 `SPEAKER_XX` 批量映射到参会人；可新建说话人并用 `assign` 把勾选段落一次划过去。
3. 1 小时会议约 300–500 段，必须虚拟滚动。
4. 报告和问答的引用点击后跳转对应段落并播放。
5. 问答用同源 `fetch` POST 消费 SSE，不用 `EventSource`。

问答页：范围选择器置顶，默认沿用上次；流式渲染；引用卡片含会议名、时间、说话人、原文。

切片 1 验收挂钩：会议详情完成约 1 小时量级转写的校对（虚拟滚动 + 批量确认），无需命令行。切片 2 验收挂钩：问答引用点击可跳到对应段落并定位播放。

## 7. 配置、隐私与备份

### 7.1 配置文件

`settings.json`（可进备份，不含 Key）：

`app.json`（应用级，在数据目录外，见 2.4）：

```json
{
  "data_dir": "",
  "host": "127.0.0.1",
  "port": 8787,
  "ffmpeg_path": "",
  "asr_home": ""
}
```

数据目录内 `settings.json`（不含 Key、不含 `data_dir`）：

```json
{
  "access_token": "",
  "allow_cloud": true,

  "report_llm_model_id": null,
  "qa_llm_model_id": null,
  "digest_llm_model_id": null,
  "max_upload_gb": 2,
  "egress_confirmed_at": null,
  "legal_confirmed_at": null
}
```

`allow_cloud` 默认 `true` 只表示**允许**把转写文本发给已配置的 LLM，**不**表示默认云转写。`asr_api_key` / `embedding_api_key` 默认空，远程 ASR/Embedding 保持关。

`app.json` 的 `data_dir` 为空时按 2.4 填充并写回。`ffmpeg_path` 空则按 2.10 查找。`asr_home` 空则程序目录 `asr`（开发为仓库根 `asr`）。exe 态其下应有 `huiyiku-asr.exe`；开发态可改用仓库 `.venv-asr`，但 **Paraformer / VAD / 标点 / CAM++ 权重仍只放在 `asr_home`**。更改数据目录只改 `app.json`。

`secrets.json` 或环境变量（优先环境变量）：

```json
{
  "asr_api_key": "",
  "embedding_api_key": "",
  "llm_api_key": ""
}
```

环境变量示例：`HUIYIKU_ASR_API_KEY`、`HUIYIKU_LLM_API_KEY`、`HUIYIKU_EMBEDDING_API_KEY`、`HUIYIKU_ACCESS_TOKEN`。

规则：

1. Key 不写日志、不进 `model_registry`、不进 Git、不打进 exe。
2. 备份会带上 `secrets.json`；文档必须提示备份副本等同于持有云账号。
3. 内网共享默认关闭。设置页开关打开后同网段可直接访问；关闭后非本机请求被拒绝。旧 `host=0.0.0.0` 且没有 `share_lan` 字段时，启动写成开启并记录警告。
4. 令牌校验使用常量时间比较。
5. Windows 上首次写入 `secrets.json` 与 `app.json` 时尽量加上仅当前用户可读写的 ACL。
6. 同一 OpenAI-compatible 服务的 Embedding 与 LLM 允许向导里填一把 Key、写入两个 `secret_ref`。

### 7.2 隐私原则

1. 知识库数据默认只存在本机。
2. **默认转写不外发音频。** 报告/问答会把转写文本发到用户配置的 LLM。外发入口必须持续可见提示。
3. `allow_cloud=false` 切断文本外发，不影响本机转写。
4. 不上传使用统计到本项目作者。
5. 日志不输出转写正文和 API Key。
6. 录音涉及他人时，须按当地法律获得参会人同意（7.4）。本机转写仍可能受录音同意法约束；把文本发给 LLM 须额外告知。
7. **不做同意管理功能**（无同意数据库、无地理位置检测、不提供法律意见）。义务在文档与首次向导的主动告知层完成。

### 7.3 备份

1. 在状态窗口点退出（不要直接杀进程，以便 checkpoint）。
2. 备份 `app.json` 与 `meeting-data\`（含 `secrets.json`）。**默认不备份 `asr\`**（体积大、可再下载）。不要只备份 `_internal`。
3. 恢复数据目录后即可浏览已有转写；**不能立刻转写新会**，除非该机已安装 ASR zip 到 `asr_home`。
4. SQLite 开 WAL，退出时 `PRAGMA wal_checkpoint(TRUNCATE)`。

### 7.4 录音合法性说明

本项目是录音转写工具。录音行为、以及是否把转写发给第三方 API，合法性由**使用者**负责。本软件按 Apache-2.0 AS IS 提供，不构成法律意见。在 GitHub 全球分发时，文档必须做**主动告知**，避免被理解为对秘密录音的放任。

| 法域 | 规则 |
|---|---|
| 美国全员同意州（加州、佛罗里达、伊利诺伊、马里兰、马萨诸塞、宾夕法尼亚、华盛顿等） | 未经所有参会人同意录音在若干州可构成**刑事犯罪**；跨州通话适用更严一方（*Kearney v. Salomon Smith Barney*） |
| 欧盟 GDPR | 第 2(2)(c) 条家庭豁免仅限**纯粹**个人/家庭活动。工作场景录同事/客户通常落在豁免之外，录音者可能成为数据控制者，负告知、删除响应等义务。把文本发到欧盟外模型还涉及跨境 |
| 中国 PIPL | 第 72 条纯个人事务豁免（类似家庭豁免，不覆盖把他人会议发给境外模型）；向第三方提供个人信息应告知并取得同意。**第 28–29 条：生物识别属敏感个人信息，须单独同意**——声纹即生物特征 |
| 一般原则 | 秘密录音在多数法域有民事或刑事风险；会议内容还可能涉及隐私权 |

项目措施（不做同意管理库、不做地理围栏）：

1. README 显著位置放录音合法性须知；完整条文级说明见 [`法律与许可.md`](法律与许可.md)。写明：转写在本机；报告/问答会把**文本**发到用户的 LLM。
2. 首次启动两次确认并记录时间：理解须符合当地法律并获得参会人同意；同意把文本发到自己配置的 API。勾选不能代替守法。
3. 导入、导出处轻量提示。

**声纹 / 本机声纹样本（后续增强，不阻塞 MVP）：** 声纹属生物识别敏感信息（PIPL 第 28–29 条单独同意；GDPR 第 9 条特殊类别原则上禁止、例外才允许）。实现前必须完成本地样本的明示同意采集流程设计，并确认目标用户法域允许；**不满足则不做**。不得与其它增强功能并列、不标注法律前提。

## 8. 测试策略

测试随切片交付。远程调用默认打到 fixture / httpx mock，CI 不访问真实外网。切片 0 在开发机用真实 Key 做一次手工长录音验收。

### 8.1 单元测试

1. 发言时长、次数、占比（含分母口径）和说话人合并后重算。
2. Chunk 切分、FTS 写入、向量二进制读写与余弦排序。
3. 报告 JSON Schema 与引用规范化匹配。
4. 接受新报告版本时行动项去重，不复制已有标题。
5. 任务幂等键、心跳回收、取消标记。
6. 远程模型默认唯一性；未确认条款不能设默认。
7. LLM 上下文预算与 map-reduce 分组上限。
8. 移动会议组后 `meeting_chunks.group_id` 一致。
9. 内网共享开关：默认关；打开后局域网可访问，关掉立即拒绝非本机。旧的非回环 host 在缺少开关字段时迁移为开启。
10. `allow_cloud=false` 时拒绝创建远程任务，本机转写仍可创建。
11. `app.json` 与数据目录分离；数据默认写在程序目录 `meeting-data`（`portable.txt` 已废弃，不再影响位置）。
12. FFmpeg 查找顺序：`app.json` → 同级 `ffmpeg\` → PATH。
13. 已有激活向量时拒绝更换 Embedding 默认；`PATCH /api/settings` 不能改注册表默认。
14. 行动项去重只发生在同一会议的报告版本之间。
15. 无已接受报告时创建组摘要返回 400。
16. 8787 被其它程序占用时启动失败，不改绑端口。
17. 会话 Cookie 头不含 `Secure`、不含 `Domain`。

切片 3 再补：术语替换、请求级 `model_id`、行动项合并、Embedding 切换回滚。

### 8.2 集成测试

1. 导入 → 预处理 →（mock ASR）→ 校对 → indexing → 报告 → 问答。
2. 编辑转写后 FTS、向量、统计按 3.17 更新。
3. 合并说话人后统计不重复累计。
4. 备份 `app.json` 与数据目录后恢复。
5. Worker 杀掉后重启继续 queued/回收 running。
6. 删除会议后媒体、FTS、报告清理；问答与摘要历史保留。进行中的任务先取消再删。
7. 1 小时转写 fixture 跑 map-reduce，断言分组覆盖全部 segment。
8. 流式上传大文件不把整文件载入内存（可用中等文件 + 读补丁断言）。
9. 打包脚本能在 CI 或本机打出 onedir；冒烟：启动 `--serve --worker`、`/api/health` 200、静态前端可开。无 Python 的真机双击作为发布门手工项。
10. 新建说话人并用 `assign` 改段落归属后统计不串。
11. `POST /api/session` 后无 Authorization 头也能 `GET .../audio`（Cookie）；响应支持 Range。
12. 第二次启动在 8787 已被本应用占用时只打开浏览器，不起第二套进程。

### 8.3 工程与许可门禁

1. Python 和 npm 锁定文件。
2. 发布节点生成 SBOM；日常 CI 只跑轻量许可检查。

5. `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md` 与 `docs/model-manifest.json` 在发布前人工核对；Release zip 内必须有前三份。
6. README 按 2.11：exe、FFmpeg、**FunASR 组件安装**、LLM Key 占位符、文本外发、合法性、SHA256；UI zip 不含 Key / FFmpeg / torch / 权重。
7. 发布 zip 体积与文件清单检查：不得包含 `meeting-data`、`secrets.json`、`.env`、真实媒体、`portable.txt`。

### 8.4 AI 评测集

开发机用 3 段个人真实脱敏样本校准（至少 1 段 ≥ 1 小时），不要把真实录音提交到 Git：

| 能力 | 试点目标 |
|---|---|

## 9. 开发里程碑

垂直切片交付。第 3、5 章领域模型一次建齐；端点和页面按切片交付。

**预计工期（单人全职）：切片 0 约 3–5 天，切片 1 约 1.5–2 周，切片 2 约 2 周（功能冻结后再打 exe，预留 2–3 天）。合计约 5–7 周。** 业余约 10–14 周。

### 切片 0：本机 FunASR 与远程 LLM 基线，3 到 5 天

1. 初始化**独立**仓库：`LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`、`.gitignore`、`.gitattributes`、`README.md` 骨架（使用者文档，不是本文）、`app.example.json`、`SECURITY.md`、`CONTRIBUTING.md`、`pyproject.toml`（先写上 `[project].version`，作为发布号唯一来源）、锁定文件。本文放入 `docs/开发方案.md`。提交 `.gitattributes` 后执行一次 `git add --renormalize .`。
2. 安装 FFmpeg 与 FunASR 组件（torch CPU + Paraformer + VAD + 标点 + 可选 CAM++）；Windows 验证中文路径；登记精确模型 ID / revision / checksum / 许可。**当天验证** `paraformer + fsmn-vad + ct-punc + campplus` 是否直接输出带说话人标签的分段时间轴；若只出 embedding，则自动聚类不进入第一版，默认 `SPEAKER_00` + 人工拆分，README 标明实验特性。
3. 脚本跑通：录音 → FFmpeg → **本机 FunASR** → `transcript.md` → 统计 → **远程 LLM** `summary.md`。长录音必须走 VAD 切段。
4. 在 **16GB 内存** 的 Windows 上转写不少于 1 小时的录音：记录峰值内存、耗时、是否出说话人、LLM token 与截断。权重必须从 `asr_home` 加载。Meetily 对照可选，不阻塞。
5. 3 段脱敏录音，至少 1 段 ≥ 1 小时。许可逐 ID 写入 `docs/model-manifest.json`。

验收：

- 不安装 Ollama、不调用云 ASR，也能出带时间戳的转写；摘要仍要 LLM Key。
- 1 小时会转写已启用 VAD，未整段灌入模型。
- **内存硬门槛：** 16GB 机器上该 1 小时会，进程峰值内存 **≤ 8GB**。超过则按顺序：① 关 CAM++；② 仍超则换更小 Paraformer 或缩短 VAD 切段；③ 把实测值写入 README 硬件表。不得只写“关 CAM++”了事（向量模型往往不是内存大头）。
- 开发态 `python -m huiyiku_asr` 与 exe 态均从同一 `asr_home` 读权重。
- 长录音报告策略证明未静默丢掉后半场。
- 即使项目在此停止，脚本已可日常使用。
- 脚本逻辑在可复用库中，切片 1 Worker 直接调用，不重写。
- 仓库按 2.11 骨架可公开：README 不是开发方案、gitignore 挡住媒体与密钥。
- CI 在无云 Key 时仍绿：只跑 mock 单元测试、许可扫描、入库卫生检查。

| 完整版能力 | 个人版处理 |
|---|---|
